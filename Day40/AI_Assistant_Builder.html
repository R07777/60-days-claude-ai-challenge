System prompt design

The assistant runs as a three-phase state machine rather than an open-ended chatbot, because a mock investor Q&A needs structure to feel real: an intake, a live grilling, and a verdict. Every model reply starts with a PHASE: line so the app always knows where the session stands, without guessing from free text.

  • PHASE: INTAKE — one plain-text question at a time, capped at six exchanges, with instructions to push back on vague one-liners rather than accept them.
  • PHASE: GRILLING — structured as FEEDBACK:, QUESTION:, and CATEGORY: lines so the UI can render feedback and the next question as distinct visual objects instead of one wall of text.
  • PHASE: VERDICT — structured SCORE: lines per category plus OVERALL: and SUMMARY:, triggered after 7–9 questions or whenever the founder asks to wrap up.

The persona is constrained hard toward bluntness: no filler praise, no exclamation points, attack the pitch never the person, and — critically — the model is told never to write the founder's answers for them. That boundary is what keeps this a rehearsal tool instead of a pitch-writing tool.

UI decisions

The visual language borrows from the artifact a real VC produces: a redlined memo. Feedback renders as a rotated, red-bordered "VC Note" card — deliberately informal and slightly askew, like a margin scribble — while questions render as a squared-off, serif "exhibit" card with a category tag, so the two feel like genuinely different moments in the conversation rather than more chat bubbles.

The sidebar acts as a case file: a live coverage checklist across the seven question categories, a progress bar, and — once the verdict lands — an animated scorecard, so a founder can see at a glance what's been tested and what hasn't.

Typing indicators, inline retry-able error cards, and a hard-coded opening question (so the first screen isn't a blank API call) round out the loading/error/empty states.

Ideas for extension

  • Tools: give the model a web-search tool to pull real comparable funding rounds or market-size data, so questions like "why is your TAM $50B?" can be checked against actual comps instead of general heuristics.
  • Memory: persist scorecards across sessions so a founder can rehearse weekly and see whether their Traction or Financials score is actually improving before the real meeting.
  • Multi-step workflows: after the verdict, auto-generate a one-page written investor memo or a follow-up email draft addressing the weakest-scored category, turning the rehearsal into a concrete next action.
